## Context

`article_state.json` 是短生命周期的处理状态：done 行 1 天后会被 cleanup 删除。此前 fetch 只从当前 feed 索引和 `article_state.json` 去重，导致同一篇文章在另一个 feed 晚些出现时会再次归档。实际 archive 中已出现同一 canonical link 的重复正文。

## Decision

- fetch 开始前扫描全部 `feeds/*.jsonl`，收集 article 记录的 guid/link key。
- 用该全局 key 集初始化本轮 `run_keys`，再叠加本轮新归档的 key。
- `article_state.json` 继续负责 pending/归档坐标/索引修复，但不再是跨 feed 去重的唯一依据。
- 全量回抓时，把全局 key 传给 fetcher，避免为已存在的文章回抓原文。
- 索引不可读时只 warning，不阻塞 fetch；冷启动仍由 `--repair-indexes` / `--reconcile-indexes` 修复。
- 去重键保持 `link:<canonical>` 和 `guid:<id>` 两种。

## Consequences

优点：

- 跨 feed 重复归档在 article_state 过期后仍能被阻止。
- 全局 key 可直接复用，无需新增持久状态文件。

缺点：

- 每轮 fetch 需要读取全部索引；当前约 500 个文件、几千条记录，成本为亚秒级，后续规模变大时需要 SQLite/全局索引。
- 索引中残留的失效 record 会阻止重新归档，直到 reconcile/repair 清理。
