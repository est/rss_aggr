## Context

`--sync` 过去会静默吞掉源站 HTTP/解析错误并返回空列表，weekly job 仍然绿色；OPML 同时有嵌套和顶层 feed 时会丢顶层条目；导入的 URL 没有校验，理论上可把 loopback/link-local/metadata 地址写入 feeds.toml，随后由 fetch 请求。

## Decision

- 源站抓取/解析失败、0 feed 结果都视为 source error，`--sync` 最终以非零退出；`sync-feeds` 不提交 `feeds.toml`。
- 单个非法/内网 feed URL 只记 warning 并跳过，不阻塞其他合法源。
- 导入的 feed/site URL 必须通过 `is_safe_public_http_url`：
  - 只允许 http(s)；
  - 拒绝 localhost、`*.local`/`*.internal`、metadata 域名；
  - 拒绝 loopback/private/link-local/reserved/multicast 等 IP；
  - 不做 DNS 解析。
- OPML 递归解析，category 取最近命名祖先；顶层和嵌套 feed 都保留。
- 格式检测优先 URL 后缀，其次内容 sniffing，不再依赖 source display name。
- 源失败与单条 URL warning 分别返回，调用方决定是否失败。

## Consequences

优点：

- 上游源站坏掉时 weekly job 会显式失败，不再静默空跑。
- 降低了 SSRF 和垃圾 feed 注入风险。
- 混合 OPML 不再丢条目。

缺点：

- 一个源站临时故障会让该次同步失败（不提交）；需要下次重试。
- 只做语法层地址校验，不解析 DNS；DNS rebinding/重定向仍需网络层防护。
