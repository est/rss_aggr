## Context

- 部分 feed 输出空 `<guid></guid>`；旧代码 `entry.get("id", entry.get("link", ""))` 不会 fallback，所有空 id 都变成 `sha256("")[:16]`，后续文章会被当作同一篇跳过。
- ETag/Last-Modified 在解析 feed 之前就被持久化。一个 HTML/WAF 页面可以写入 validator；下一轮得到 304 后被当作健康 feed，永久不产出文章。

## Decision

- 条目身份按顺序取：非空 `id` → 非空 `link`；两者都没有则跳过该条目，不生成常量 GUID。
- 条件请求 header 只在 feed 成功解析后写入。
- 304 仍是成功状态，并可刷新 validator。
- 解析失败时删除该 feed 的 `etag` / `last_modified`，避免下一次 304 继续掩盖错误。

## Consequences

优点：

- 空 GUID feed 不再丢文章。
- 被 WAF/反爬页面污染的 validator 不会永久饿死 feed。
- 失败状态可以继续走 error/disable/retry 生命周期。

缺点：

- 无 id 且无 link 的条目会被丢弃；这类条目本来也无法归档/渲染。
- 解析成功的空 feed 仍可能写入 validator；这是服务端语义，不在本地强行判定。
