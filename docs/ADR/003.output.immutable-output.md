## Context

RSS 文章分类后需要存储结果。需要决定：
- 是否允许修改已输出的文件
- 如何处理重复运行
- 如何保证历史数据完整性

## Decision

Output 采用 append-only（只追加）语义，而不是严格不可变：

- 已经写入的行永不删除；
- 过去日期的 `output/YYYY/MMDD.md` 不重写，除非是幂等的追加（去重后写入新行）或修复（如旧表头升级）；
- 同一天的文件允许在后续运行中扩展，新文章去重后追加；
- 不覆盖已有文章行，不删除历史文件；
- 已发布的 HTML 不受影响。

## Consequences

优点：
- 历史数据完整，可追溯
- 无需担心运行顺序导致数据丢失
- 同一天多次运行可以持续补充新文章
- GitHub Pages 渲染稳定

缺点：
- 修正分类错误需要手动编辑或新建修正条目
- 同一天的文件可能因重复运行而增大（但去重机制控制）
- “修复”路径必须保持幂等，否则会破坏 append-only 保证
