## Context

每日页和 per-feed 页把每篇文章整段摊开：

- 一天 60 篇时页面极长，读到第 3 篇就要滚屏；
- per-feed 页面还会在滚动时对每一条都发 Range 请求，把折叠状态不存在的“列表”和“正文”混在一起；
- 想找某一篇只能靠滚动，没有可点的把手。

浏览器原生就有 `<details>` / `<summary>`，不需要框架，也不需要 JS 就能展开收起。

## Decision

- 每篇文章渲染成一个 `<details class="article foldable" id="<anchor>">`：
  - `<summary>` 里放标题（`<h2 class="title">`）和 meta 行（作者、时间、feed 链接）；
  - 正文放在 `<summary>` 之后，默认收起；
  - 锚点 id 仍挂在 `<details>` 上，`_daily_url` 契约不变。
- 标题本身是折叠把手，因此标题是纯文本：`<summary>` 里的链接会直接跳转而不是展开条目。
  源站链接移到 meta 行（每日页的 “Original”）或正文上方的链接行（per-feed 页）。
- per-feed 页面的条目同样折叠，正文改成展开那一条时才按 `_archive` 坐标发 Range 请求；
  滚动预加载（IntersectionObserver）取消。
- `assets/site.js` 负责两件 JS 才有的事：
  - “Expand all / Collapse all”（无 JS 时不显示，按钮默认 `hidden`）；
  - 深链（`#<anchor>`）指向的条目自动展开并滚动到可见位置。
- 折叠是纯展示层决定，不影响 archive、feed index、JSON Feed 的任何契约。

## Consequences

优点：

- 每日页变成一屏标题列表，想读哪篇点哪篇；
- per-feed 页面只为真正展开的条目发请求；
- 折叠不依赖 JS（原生 `<details>`），脚本只做增强。

缺点：

- 标题不再是源站链接，源站入口挪到了 meta 行；
- 深层链接需要 `site.js` 才能自动展开（无 JS 时仍会跳到对应条目，只是保持折叠）。
