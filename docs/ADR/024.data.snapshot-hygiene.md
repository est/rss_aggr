## Context

旧快照存在几个问题：

- `output/` 已不再更新，却一直留在 data 分支；
- data 是 orphan branch，没有 `.gitattributes`，checkout 可能改写 archive/feeds 的 LF 字节，破坏 offset；
- 快照计时基于 data 分支最后一个 commit，人工修 feed 的 commit 会无限重置 20 小时窗口；
- cache key 只含 `run_id`，GitHub re-run 使用相同 run_id，可能精确命中失败尝试的缓存。

## Decision

- data 快照 allowlist 增加 `.gitattributes`，内容固定 `archive/**/*.md` 和 `feeds/*.jsonl` 为 LF。
- 新快照不再保留或写入 `output/`；远端旧副本在清理阶段删除。
- 快照计时只参考 subject 匹配 `^data: snapshot ` 的 commit；人工 commit 不重置计时。
- cache key 使用 `rss-runtime-${run_id}-${run_attempt}`。
- push 被拒后先 unshallow，再 `pull --rebase` 一次。
- data 仍是事实来源，cache 仍是可驱逐的热副本。

## Consequences

优点：

- archive/feed index 在 checkout 后仍保持 byte offset 稳定。
- data 分支更小、职责更清晰。
- 人工修复不会延迟正常快照。
- re-run 不会误用失败尝试的 cache。

缺点：

- 每次快照要维护 `.gitattributes`；allowlist 拒绝未知路径。
- 第一次新快照会删除远端 `output/`，依赖它的外部脚本会失效（它本来也不是对外接口）。
