## Context

`article_state.json` 的 loader 在“合法 JSON 但结构错误”时返回空列表；CI 随后会把它写成空状态，导致 pending 元数据和索引修复标记被静默清除。`feed_state.json` 也没有结构校验，错误结构会在后续步骤触发 `AttributeError`。这些都会让损坏看起来像“没有文章/没有 feed”。

## Decision

- `article_state.json` / `feed_state.json` 的结构损坏必须 fail closed：
  - migrate、report、check、fetch、classify 遇到 corrupt 直接报错；
  - 不把损坏文件重写为空状态。
- `feed_state.load_state` 校验：
  - 顶层是对象；
  - `feeds` 是对象；
  - 每个 feed 条目是对象。
- `step_check` 和 `step_report` 在构建报告前显式校验 article state。
- 迁移/恢复失败时 CI 保留 `.restore-data-ok` 语义：校验步骤不通过就不写 cache/data 快照。

## Consequences

优点：

- 状态损坏会阻止运行，而不是悄悄丢数据。
- 错误信息能指出具体文件和结构。

缺点：

- 损坏时需要人工恢复，不能靠自动重建继续跑。
- 旧版本可能存在的非标准结构需要先迁移或修复。
